# 提示词：把网站、产品或项目变成一篇可用内容

复制以下整段并填写资料。优先用外部 Agent 起稿，再在文章页添加并保存；不要求先配置站内自动写作。示例见[项目资料](../examples/project-brief.md)。

```text
请帮我为 aimeGeo 准备一份可保存的内容任务和文章草稿。

项目/产品名：[填写]
官网或公开资料：[URL 或资料文本]
目标读者：[谁，在什么场景遇到什么问题]
推广主题：[希望讲清的一个主题]
目标平台：[填写；不清楚则先建议]
内容类型：[图文 / 视频]
语气及字数：[填写]
必须保留的事实与来源：[填写]
不能公开的信息：[填写分类，不贴真实密钥或个人隐私]

请先核对公开来源，区分已确认事实、推断和缺项；无法访问的网页如实说明。
资料不足时先给问题与大纲，不编造价格、认证、用户数量、合作或使用案例。
不要把本地示例、模板内容当作真实产品能力。

输出顺序：
1. 项目摘要、目标读者、主题与原始来源。
2. 三个标题候选及推荐理由。
3. 一篇完整草稿：开头直接回答读者问题，随后写适用场景、步骤、示例、限制与常见问题。
4. 说明、标签、封面文字、配图建议和可点击的来源链接。
5. 事实核对表与仍需我补充的信息。

自然使用产品名及相关术语，不堆砌关键词、不伪装独立测评。
把“提及”“引用”“公开发布”分别表述，不承诺 GEO 必收录或固定排名。
如果是视频，输出脚本和真实素材需求，不能用正文链接冒充已制作的视频。
封面可建议 Image2、豆包 Seedream 或 Remotion，分别说明实际配置、外部费用与模板尺寸条件。

若有本仓库，先读 docs/workflow.md、docs/platforms-and-models.md；
准备后说明如何进入正式工作台：
资料 https://geo.aimmme.com/ag01/geo/prep/knowledge-base
文章 https://geo.aimmme.com/ag01/geo/writing/articles

首条流程：外部 Agent 生成草稿→文章页“添加文章”→填写文章标题、摘要、分类、
正文内容（Markdown）→添加图片或图片链接→选择内容类型→点击“创建”。
标签按目标投稿平台准备，不假称文章表单有标签字段。重新打开确认保存结果；
无实际网页操作能力时给出手动步骤，不假称已保存。
站内写作任务是可选入口，不是新手前置条件；如需但未配置，查官方帮助或联系支持。
协作工具图标不表示所有 Agent 都能直接在站内自动执行。
此任务仅制作内容，不对外投稿。
```
